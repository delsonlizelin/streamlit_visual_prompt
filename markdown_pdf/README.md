# Markdown PDF

一个轻量的双页面 Streamlit 应用：把中文、英文或双语 Markdown 转成适合长时间阅读的 PDF，或从粘贴文本、Markdown、TXT、普通文本型 PDF 和公开文章网址直接生成可分享的高清摘要长图。两个页面使用顶部的单一按钮切换，不依赖侧边栏；页面为 Streamlit Cloud 固定工具栏保留安全区域，并针对手机窄屏调整编辑器、选项和触控按钮。

PDF 页面提供三种确定性版式：

- **电脑端**：A4、11.2 pt 正文、左下页码。
- **平板端**：132 × 201 mm、12.1 pt 正文，匹配 iPad mini 竖屏比例、无页眉、居中页码。
- **手机端**：9:16、12.8 pt 正文、短行宽、无页眉、居中页码。

裸 URL 会使用专门的折行与弱化样式，避免长路径、查询参数和 DOI 越过窄页面边界；带可读标题的普通链接保持正文样式。

## 从 GPT 网页会话生成 Markdown

页面顶部提供“复制 GPT Markdown 格式要求”按钮。按钮只复制渲染器的格式约束，不显示提示词正文，也不包含主题、风格或写作要求；可以直接附加到用户自己的 GPT 提示词中。

提示词要求模型只生成一个 H1，以 H2/H3 组织正文，使用渲染器支持的标准 Markdown，并排除 HTML、YAML front matter、公式、Mermaid、脚注、本地图片和整篇外层代码围栏。生成结果仍会经过页面现有的导出前检查。

## 导出前检查

编辑器会在生成前运行本地兼容性检查，提示：

- 未闭合代码围栏、缺少或重复 H1、标题层级跳跃；
- Mermaid、LaTeX 公式、原始 HTML 和不安全链接；
- 本地图片、缺失替代文本、宽表格和长 URL。

检查不调用模型，也不会修改原始 Markdown。未闭合代码围栏或不安全链接等红色错误会阻止导出，其余提醒允许继续生成。PDF 生成后还会检查空白页，以及正文中的链接、段落、列表、代码、表格、图片和引用是否越过页面内容边界。

## 文章摘要

独立的“摘要长图”页面支持上传、粘贴或读取文章，并提供：

- 在一个输入控件中选择粘贴文字、上传 Markdown / UTF-8 TXT / 普通文本型 PDF，或读取公开文章网址；
- 公开网页与微信公众号文章会先提取为可编辑正文；登录、验证码和访问频率限制可能导致读取失败；
- 核心摘要、按章节梳理两种内容结构，以及直接摘要、易懂解释两种可组合的讲述方式；
- 标准篇幅和详细展开两档长度；界面根据内容结构与讲述方式显示中文目标字数和英文目标词数，详细展开会保留更多论据、数据、例子、限制与推理过程；
- 可选的补充要求输入框，用于把关注重点、语气或展开方式加入当前摘要 Prompt；
- DeepSeek V4 Flash 和 V4 Pro 两种模型可选；默认使用成本较低的 Flash；
- 跟随原文、简体中文、English 三种输出语言；
- 点击一次完成内容提炼与手机长图排版，模型直接返回经过校验的结构化摘要，不生成或暴露 Markdown 中间稿；
- 生成 1227 px 宽的 3× 连续高清 PNG 长图，支持浏览器原生分享、下载和 iOS 长按保存；
- 灰白画布、白色内容分区与克制橙色重点组成适合手机阅读的信息层级；
- 保留重要数字、日期、名称、限制条件、因果关系和否定表达；
- 使用带明确字段的 JSON 封装原文、任务配置和补充要求，降低文稿中提示词注入内容的影响；
- 在本地检查问句标题、复合条目、重复条目、数字来源与高亮密度，问题只提醒人工核对，不擅自改写语义；
- 生成后可直接修改结构化 JSON 并在本地重新排版，不再次调用模型；
- 一键复制当前内容结构、讲述方式、系统规则和语言要求，正文位置使用安全占位符。

上传文件后，下载文件名默认继承原文件名；读取网页时默认继承文章标题；直接粘贴时，摘要页使用 `summary`，PDF 页面使用 `longread`。原文输入始终可见，三项主要摘要选择位于生成按钮之前，按钮文案会显示当前方案；编辑后主按钮会明确变为“重新生成”，同一文件也可手动重新读取。摘要页只使用 DeepSeek Chat Completions API。请求使用 JSON 输出，单篇上限为 30 万字符；服务端会校验标题、署名、导语、编辑分区、原子要点和重点短语，再由确定性模板直接生成长图。未配置 Key 时页面仍能读取网页、上传和编辑，但生成按钮会禁用。点击生成即表示同意把当前输入发送到 DeepSeek，不再提供重复确认框。

提示词要求中性、直接和忠实。模型先建立文章的一阶议题覆盖图，再从中选择 3–6 个自然分区组织标准摘要；演讲中明确列出的议程项和编号原则不得被静默省略，一个编号成员必须对应一个独立要点。演讲已有清晰大纲时优先沿用其议题骨架，没有新增信息的结语不会另造“未来方向”章节。每条要点必须只承载一个可独立阅读的判断，并尽量保留主体、动作、对象、数字、时间、条件和因果依据；来源判断会明确归因，不把作者观点伪装成事实。中英逐段对照只计为一份信息，会员引导、评论区、转载说明、翻译模型署名和 OCR 残片会被视为平台噪音。标题和分区不强求问句或对称句式，同一摘要的问句标题不超过一半；高亮也不是配额，避免整齐但机械的机器摘要节奏。核心内容优先于仪式性结论，风险、限制和反例只放回它们真正影响的要点，不单独堆出泛化免责声明。导语只有在全文存在单一、强而明确的总判断时才出现，多议题文章允许直接进入分区。讲述方式独立于内容结构：直接摘要保留必要术语和信息密度；易懂解释只把原文已有的背景、术语和推理织入相关章节，不补充外部知识。原文信息不足时允许少于目标篇幅，不重复或虚构内容凑字数。

长图直接消费结构化摘要：标题与真实作者/主要发言人组成紧凑题头，编辑分区使用连续编号与细分隔线，关键数字、结果和结论变化可以获得 0–2 处精确重点，且只在与正文完全匹配、互不重叠时着色。长图与网页优先使用项目内置的 Noto Sans SC 可变字体；移动长图只保留画布边沟、分区内边与列表悬挂缩进，不再叠加正文页内边，因此约八成画布可用于文字，并配合紧凑行距与分区节奏减少无谓换行。整体保持冷灰画布、白色阅读纸、石墨文字与克制朱橙色，不添加文章快照、虚构 LOGO 或固定免责声明。如果摘要超过 Chromium 的稳定单图高度，页面会直接提示缩短原文或降低详细程度。

## API 与隐私

PDF 转换和上传 PDF 的文字提取完全在 Streamlit 应用的运行环境中完成，不调用 DeepSeek、OpenAI 或其他模型服务。粘贴完整文章网址后会自动读取，无需回车或额外按钮；网页仅允许公开的 HTTP(S) 地址、最多读取 25 MB。摘要页单个 Markdown、TXT 或 PDF 文件最多上传 100 MB。本机、内网和带账号密码的网址会被拒绝。只有点击摘要页的“生成摘要”后，编辑器中的正文才会发送到 DeepSeek。

本地开发时，创建 Secrets 文件并填写自己的 Key：

```bash
cd markdown_pdf
mkdir -p .streamlit
$EDITOR .streamlit/secrets.toml
```

```toml
DEEPSEEK_API_KEY = "your-key"
DEEPSEEK_MODEL = "deepseek-v4-flash"
DEEPSEEK_BASE_URL = "https://api.deepseek.com"
```

`.streamlit/secrets.toml` 已被 Git 忽略。不要把真实 Key 写进代码、提交到仓库或粘贴到公开日志。

应用启动时会自动读取 Key，但只有点击“生成摘要”才会调用 DeepSeek 和消耗额度。

## 依赖

Python 依赖写在 `requirements.txt`：

- `streamlit[pdf]`：界面、上传、PDF 预览与下载；
- `Markdown`：Markdown 解析；
- `bleach`：清理上传内容中的不安全 HTML；
- `pypdf`：从普通文本型 PDF 提取带页面顺序的可编辑文本；
- `playwright`：控制 Chromium 生成带 CSS 分页的 PDF。

摘要请求使用 Python 标准库发送，没有引入 DeepSeek SDK 或额外 AI 框架。Prompt 把原文放在可变摘要设置之前，使同一文章修改模式并重新生成时更容易复用 DeepSeek 默认开启的前缀缓存。仅在 HTTP 429、500、503，或响应为空、JSON 无效、结构校验失败时重试一次；输出达到长度上限等确定性错误不会盲目重试。

仓库根目录的 `packages.txt` 会让 Streamlit Community Cloud 安装：

- `chromium`：PDF 渲染引擎；
- `fonts-noto-cjk`：云端中文字体；
- `fonts-liberation`：英文字体后备。

Paged.js 已作为本地静态资源放在 `longread_pdf/assets/`，运行时不需要 Node.js，也不会从 CDN 下载脚本。

## 本地运行

建议使用 Python 3.12：

```bash
cd markdown_pdf
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run streamlit_app.py
```

macOS 会自动寻找 `/Applications/Google Chrome.app`。Linux 默认寻找 `chromium`。也可以通过 `CHROMIUM_PATH` 指定浏览器可执行文件。

## 部署到 Streamlit Community Cloud

1. 把仓库推送到 GitHub。
2. 在 Streamlit Community Cloud 中新建应用。
3. 选择这个仓库与分支，入口文件填写 `markdown_pdf/streamlit_app.py`。
4. Python 版本选择 3.12，然后部署。
5. 如果需要摘要，在应用的 **Settings → Secrets** 中填写与上方相同的三项配置，然后重启应用。

只使用 PDF 功能时，不需要配置任何 API Key。

## 支持范围

支持普通标题、段落、强调、引用、列表、链接、HTTPS 图片、代码和简单表格。复杂公式、宽表格、Mermaid 或学术论文型排版不在第一版范围内；导出前检查会明确提示这些内容。

## 测试

```bash
python -m unittest discover -s tests -v
python scripts/smoke_test.py
python scripts/summary_export_smoke_test.py
```

第一组冒烟测试会用同一份中英文回归文稿生成 A4、Tablet 和 9:16 三份长文 PDF。第二组会生成三种紧凑摘要 PDF、Tablet / Mobile 两张高清长图，并把生成的 PDF 重新导入以验证文字提取；检测到空白页、正文溢出、解析失败或异常图片尺寸时会失败。

## 后续版本

PDF 与摘要保持为两个独立页面，但摘要可以一键送入 PDF 编辑器。复杂的 AI 格式润色、多模型切换、账号和历史记录暂不加入；是否继续开发以真实使用反馈为准。详细边界见 [`ROADMAP.md`](ROADMAP.md)。
