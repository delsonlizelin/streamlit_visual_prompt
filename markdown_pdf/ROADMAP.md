# Markdown PDF 产品路线图

## 产品结构

应用长期保持两个清晰入口：

1. **Markdown 转 PDF**：当前已完成。确定性排版，不需要模型 API。
2. **格式调整与摘要**：下一阶段。先诊断和修复 Markdown，再按需要生成摘要。

AI 只能是增强层，不能成为 PDF 转换的前置依赖。未配置 API key 时，用户仍然可以完成上传、编辑、兼容性检查、排版、预览与下载。

## V1.1：格式调整

目标不是“重写文章”，而是把输入稳定转换成渲染器支持的 Markdown 子集。

### 确定性检查优先

在调用模型前先运行本地诊断器，检测：

- 未闭合的代码围栏、强调标记、链接和括号；
- 裸 HTML、脚本和不安全链接协议；
- Mermaid、数学公式、复杂或过宽表格；
- 本地图片路径、无效图片地址和缺失替代文本；
- 跳级标题、重复 H1、缺少封面标题；
- 可能破坏 CJK 强调解析的标点边界；
- 当前长文 CSS 不支持或容易溢出的结构。

能够机械修复的问题在本地完成。需要判断的问题才交给模型。

### AI 格式润色约束

- 保留事实、语气、段落顺序和全部信息；
- 不扩写、不删减、不总结正文；
- 只修改 Markdown 结构与必要的连接文字；
- 输出必须落在渲染器支持的语法白名单内；
- 无法安全转换的内容用明确的兼容性提示标记；
- 展示修改前后差异，由用户确认后覆盖编辑器内容；
- 格式润色和内容润色必须是两个不同操作。

### 格式兼容提示词骨架

```text
你是 Markdown 兼容性编辑器，不是文章改写者。

任务：把输入转换为指定渲染器支持的 Markdown，同时保持原文信息、语气、顺序和含义不变。

允许：修复标题层级、强调边界、列表缩进、代码围栏、链接、图片说明和简单表格；把不支持的结构转换为可读的标题、段落、列表、引用或代码块。

禁止：总结、扩写、删减、杜撰、改变结论、添加装饰性模块、输出解释性前言。

输出：只返回修复后的 Markdown。无法无损转换的片段保留原文，并在其前一行加入“> 兼容性提示：……”说明原因。
```

正式实现时应使用结构化输入，额外传入本地诊断结果、支持语法清单和输出长度上限。

## V1.2：摘要

研究目标是参考微信小程序“总结一下鸭”的用户可见功能与交互路径，提炼其任务拆分和输出结构，再设计原创提示词。只研究公开可观察的产品行为，不复制专有代码、隐藏提示词或受保护内容。

需要验证的功能假设：

- 一句话摘要；
- 标准摘要与详细摘要；
- 核心观点 / 关键结论；
- 分章节摘要；
- 行动项、待办或问题清单；
- 面向不同读者的摘要；
- 摘要长度、语言与语气控制；
- 重要原句引用及其来源段落定位。

研究完成后再冻结提示词，不把以上假设直接当作该小程序的真实功能。

### 摘要提示词设计原则

- 忠实于输入，不加入外部事实；
- 明确区分原文事实、作者观点和模型归纳；
- 保留关键数字、日期、专有名词、限制条件和否定表达；
- 长文先分块提取，再进行全局合并，避免只总结开头；
- 为每条要点保留可追溯的章节或段落标识；
- 支持中文、英文和双语输出；
- 格式润色结果与摘要结果分别保存，不能互相覆盖。

## 模型与密钥

- 首选实现为通用 OpenAI-compatible provider 接口；
- DeepSeek 可以作为第一种可选提供商；
- 密钥只从 Streamlit Secrets 读取，例如 `DEEPSEEK_API_KEY`；
- 仓库、日志、缓存和下载文件不得保存密钥；
- 调用前明确提示正文将发送到所选模型服务；
- 提供“不使用 AI，仅做本地兼容性修复”的路径。

## 验收标准

- 原始 Markdown 永远可以恢复；
- 每次 AI 修改都有可审阅差异；
- PDF 转换不因未配置 API 而失效；
- 模型输出必须再次通过本地兼容性检查；
- 摘要中的数字、名称和否定关系有自动一致性检查；
- 长文、中文标点、混合语言、代码块和简单表格均有回归测试。
